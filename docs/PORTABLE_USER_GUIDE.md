# 大创报销材料助手：离线使用教程

## 0. 安全本地识别与工作区清理

电子 PDF 会优先在本地读取可选文字和表格坐标，扫描 PDF 会在独立子进程中调用随包 PaddleOCR；即使 OCR 超时、原生库崩溃、结果损坏或模型不完整，主窗口也不会退出，原始票据仍会进入第 3 步供手工确认。导入入口只接受 PDF，避免把同目录中的付款截图误当成发票。导入前界面会显示已选择的文件名和数量；如果没有选中文件，程序会停留在第 2 步并提示重新选择。

首页按项目名称显示“已有工作区”，并提供“删除工作区”。即使工作区状态文件损坏，也可以从首页删除。这个操作会删除该工作区内的票据副本、导出文件和备份，无法恢复；仅用于清理错误或已经不需要的测试工作区。需要保留的有效工作区，请先点击“下载备份”。

## 1. 这是什么

这是一个完全在 Windows 本机运行的报销材料整理工具。它用于把多张原始票据整理为符合指定额度上限的一组材料，并生成入库单、出库单和重命名后的原始票据副本。

- 不需要登录账号。
- 不需要支付 API 费用。
- 不需要安装 Python、PaddleOCR 或其他开发环境。
- 票据、模板、工作区和导出结果默认只保存在本机。

## 2. 先看发布包结构

请保留整个发布文件夹，不要只复制其中的 EXE：

```text
RMReimbursementMaterials.exe  程序入口
_internal\                     程序运行库和本地 OCR 模型，不能删除或改名
README.md                     本使用教程
```

如果要通过微信、QQ 或网盘发送给其他人，请先压缩整个发布文件夹；接收方必须完整解压后，再双击 `RMReimbursementMaterials.exe`。

## 3. 第一次启动

1. 双击 `RMReimbursementMaterials.exe`。
2. 首次启动会出现“**大创报销材料助手**”窗口。它不需要联网；启动时可能需要几十秒初始化本地 OCR 模型。
3. Windows 若显示安全提示，只应在确认文件来自可信队内来源时选择继续运行。
4. 首页点击“创建工作区”，填写本次整理任务的名称，例如“2026 大创材料采购”。

程序默认把工作区保存到：

```text
%LOCALAPPDATA%\RMReimbursementMaterials
```

删除发布包不会自动删除工作区；同样，工作区中的票据也不会被程序上传到网络。

## 4. 六步完成一份报销材料

### 第 1 步：使用内嵌模板

发布包已经内嵌经确认的入库单和出库单 Excel 模板。创建工作区后程序会自动使用它们，因此无需填写模板路径、上传模板或选择 OCR 提供者。

如学校以后正式更换表格规范，请由维护人员替换发布包中的模板并完成打印复核后再制作新版发布包；日常整理票据时不应改动模板。

### 第 2 步：导入票据

只选择发票 PDF，不要选择付款记录图片。每个文件不能超过 25 MB；多份合规票据可以同批导入。也可以先从一个文件夹导入一批，再点击第 3 步的“继续导入更多 PDF”从其他文件夹追加，后续批次不会覆盖已有票据。如果一次选择的文件非常多而提示“总大小过大”，请拆成多批导入。

原始导入文件会复制到当前工作区，不会被改名、覆盖或移动。

### 第 3 步：确认票据

程序会尝试本地识别日期、价税合计金额、商家和票据号。每行左侧会明确显示“待确认”或“已确认”。请核对并手工修正：

- 金额必须填写价税合计，并确认大于 0。
- 勾选“材料”仅用于能够进入入库/出库单的材料票据；非材料票据不会参与额度分配。
- OCR 识别内容只是辅助，任何不确定的数据都应以原始票据为准。
- 如导入了错误票据，在该行“操作”列点击“删除”并确认。程序会删除工作区内的导入副本，同时从全部额度分配中移除该票据；不会删除你最初选择导入的外部原文件。
- 全部字段核对完成后可点击“确认全部票据”；任意一张金额无效时整批不会保存，并会指出需要修正的票据。
- 也可点击单行“确认此张”。页面会提示还剩多少张未确认，不再出现点击后看似没有反应的情况。

如窗口宽度较窄，确认票据表格可横向滚动；确认和删除按钮始终位于最右侧“操作”列。

### 第 4 步：设置额度

为每个可报销项目新建一张额度卡，填写名称和上限金额。例如：`大创项目 A - 1500`，金额填写 `1500.00`。

- 可创建多个相同金额的额度卡，适用于多个同额度项目。
- 每张票据只能分配给一张额度卡。
- 任一额度卡内的票据总金额不得超过其上限。
- 名称或金额填错时，可在当前页面直接修改并点击“更新额度”；新额度不能低于已分配票据的合计金额。
- 不再使用的额度可点击“删除额度”。对应的自动明细会删除，但原票据仍保留，可重新分配到其他额度。

### 第 5 步：分配票据并填写入出库明细

入库单和出库单模板已经内嵌在程序中；每次使用时只需要导入原始票据，不需要再次上传模板。可以点击“自动分配已确认票据”获得建议，也可以为每张额度卡手工勾选票据。自动分配会尽量提高可报销票据总额，大批量票据也会限制计算量以避免窗口长时间卡住，因此最终结果仍应由经办人核对。对尚未手工填写的额度卡，自动分配会生成一行一票的可编辑草稿。只有商品结构唯一、数量明确，并且“数量 × 含税单价”与已确认的价税合计在一分误差内一致时，名称、规格、单位、数量、单价和金额才会全部填入并标记为“已校验”。无法严格核验时只填日期、供应商和价税合计，其余字段留空，绝不会把税额、未税金额、折扣、发票号或整页文字猜成商品明细。

修改票据金额、删除票据或重新分配票据后，程序会刷新自动草稿；已经点击“保存明细”的手工数据不会被后续自动分配覆盖。

随后填写入库/出库明细。每一行至少应按学校模板填写日期、名称、规格、单位、数量、单价、金额和供应商。该额度卡的明细合计必须与已分配票据的价税合计一致。

程序不会填写需要手写、签字或盖章的栏位；请在打印后按学校规范完成。

### 第 6 步：检查并导出

检查页面会显示每张额度卡的票据合计、明细合计和剩余额度。只有以下条件全部满足才能导出：

- 所有已分配票据均已确认。
- 票据合计不超过额度上限。
- 明细合计与票据合计一致。
- 入库单、出库单模板校验通过。

点击“生成材料包”，然后点击“打开目录”。每个额度卡会生成一个独立文件夹，内容严格只有：

```text
入库单.xlsx
出库单.xlsx
原始票据\
```

第 3、5 步会显示与最终导出一致的票据名，例如 `260711_01_100.88.pdf`，而不是程序内部的存储编号。导出的原始票据副本会按 `YYMMDD_序号_金额.扩展名` 重命名，便于打印整理。导出包中不会包含 `票据识别记录.md`、工作区数据或 `receipts.json`。

## 5. 备份与恢复

在任一工作区页面可下载压缩后的 ZIP 备份。程序在生成备份时会按自身恢复限制检查内容，恢复备份会创建新的工作区，不覆盖已有工作区。

建议在导出前和提交材料后各保存一份 ZIP 备份到受控的本地磁盘或队伍网盘。

## 6. 常见问题

### 程序窗口打不开或一闪而过

确认 `RMReimbursementMaterials.exe` 与 `_internal` 文件夹仍在同一目录。不要从压缩包内直接运行，也不要单独复制 EXE。

### OCR 没有识别出扫描 PDF

确认扫描 PDF 清晰、票据没有严重倾斜；必要时在第 3 步人工填写日期、金额、商家和票据号。如果 OCR 工作进程超时或异常退出，识别说明中会显示原因，但票据仍会保留。程序允许人工确认后继续，不会用模拟 OCR 数据替代真实金额。

### OCR 报 `inference.pdmodel` 无法打开

若 Windows 用户目录含有特殊字符，可在启动前由管理员设置一个可写的英文路径：

```powershell
setx RM_MATERIALS_OCR_HOME C:\RMReimbursementMaterials
```

重新打开程序后再试。此设置只改变 OCR 模型缓存位置，不会上传数据。

### 无法导出

回到第 6 步查看红色提示，最常见原因是票据金额超过额度、明细合计与票据合计不同，或模板文件不符合要求。

## 7. 提交前人工复核清单

在正式打印和报销前，请经办人使用真实学校模板和脱敏票据至少完整演练一次，并确认：

1. 入库单、出库单的字段位置与学校模板一致。
2. 票据日期、价税合计、商家、票据号均已人工核对。
3. 每张额度卡的票据总额不超过上限。
4. 每张额度卡的明细总额等于票据总额。
5. Excel 打印预览的页边距、合计、大写金额、签字和盖章位置符合本校要求。

本工具负责整理和生成材料，不替代学校财务人员对报销合规性的最终审核。
